# DEC-045：冻结最小输入、演示文件限制与分级冲突处理

## Type

Product / Input Contract / File Limits / Conflict Handling

## Status

Accepted — Amended by DEC-059

> **Current amendment:** [DEC-059](dec-059-targeted-needs-input-action-request-model.md) 将缺失与冲突的 Needs Input 交互具体化为由当前真实阻断派生的有限结构化行动请求；本决定的最低输入、文件限制和冲突分级保持有效。

## Decision

### Task 创建门禁

创建任务至少需要：

- 商品名称或临时工作名称；
- 商品品类；
- 本次推广目标。

满足以上三项即可创建稳定 `task_id` 并进入单任务工作台。创建任务不等于 Fact Stage 已可运行；系统必须分别展示任务已创建与事实资料是否达到可运行条件。

### Fact Stage 可运行门禁

Fact Stage 至少需要：

- 商品主要用途的明确描述；
- 至少一个可用的当前商品来源；用户在结构化表单中的手动输入可以构成该来源，不强制上传文件；
- 除名称和品类外，至少一个具有直接来源支持的核心商品属性；
- 不存在尚未解决的阻断性商品身份冲突。

该门禁沿用 DEC-026 的 Minimum Runnable Input。价格或价格区间、商家当前卖点不是所有商品和任务都必须具备的全局硬必填项；缺失时，如与当前任务相关，应作为资料限制、受影响结论和建议补充项展示，而不是机械阻断任务创建或 Fact Stage。增强与可选资料仍遵守 DEC-005 / DEC-044：缺失不得阻断可可靠完成的基础流程。

本决定冻结产品字段语义和必填边界，不冻结最终字段名、数据类型、JSON Schema、API 请求结构、数据库列或前端控件。

### 首个演示的默认文件限制

首个演示采用以下默认上限：

- 每个任务最多 20 个文件；
- 单个文件最多 10 MB；
- 单个文本型 PDF 最多 100 页；
- 单个评论 CSV 最多 10,000 行。

这些上限允许通过运行配置调整，但上述默认值属于演示产品契约，必须有契约测试。文件类型继续以 DEC-041 为准。

单个文件超过限制、格式不允许、不可读或受密码保护时，只拒绝该文件并说明原因；同一次提交中已经接受的文件保持有效，不因一个失败文件整体回滚。若移除失败文件后仍未满足 Fact Stage 门禁，任务进入用户可见的 Needs Input，并说明所缺条件与恢复方式。

### 分级冲突处理

冲突按其是否会破坏当前商品身份或诚实事实层来分级：

1. **阻断性冲突：** 涉及当前商品 / SKU / 型号 / 版本范围，或后续事实层必须依赖且无法诚实并存的关键商品事实。工作流进入 Needs Input，展示冲突值、对应 Source Version / 证据位置、受影响阶段，以及用户可以选择、纠正或补充资料的动作。模型不得静默选择一个值并写成事实。
2. **非阻断性证据差异：** 不影响当前商品身份，也不妨碍形成诚实基础事实层的来源差异。流程继续，但必须显示资料限制、受影响结论及相应证据，不得把差异隐藏为单一确定结论。

是否阻断以“当前阶段能否形成诚实、可追溯的基础结果”为原则判断，不建立覆盖所有低概率 Case 的泛化防御目录。`Needs Input` 仍是产品交互语言，不是本决定冻结的 API 或数据库状态枚举。

## Alternatives Considered

### P-07B：沿用 DEC-005 的全部旧字段作为全局硬必填

- 优点：表面上资料更齐全。
- 缺点：价格与商家卖点并非所有任务都成立，会把增强资料机械化为阻断项，并与 DEC-026 的最低事实契约不一致。
- 结论：不采用。

### P-07C：只以名称、品类和目标启动完整流程

- 优点：输入摩擦最低。
- 缺点：不足以形成有来源的基础事实层。
- 结论：不采用；三项只用于创建任务，不代表 Fact Stage 可运行。

### P-08B：更保守的 10 文件 / 5 MB / 50 页 / 5,000 行

- 优点：本地资源压力更低。
- 缺点：对演示资料包限制偏紧，且没有当前证据表明需要该收缩。
- 结论：不采用。

### P-08C：不设产品层限制

- 优点：规则最少。
- 缺点：错误反馈与演示可复现性依赖解析器偶然行为。
- 结论：不采用。

### P-09B：所有冲突一律阻断

- 优点：规则表面统一。
- 缺点：会让无关差异过度阻断流程。
- 结论：不采用。

### P-09C：模型自动选择最可能值

- 优点：流程中断最少。
- 缺点：可能把未经用户裁决的冲突值写成事实，破坏证据追溯与用户最终判断权。
- 结论：不采用。

## Reason

任务创建与 Fact Stage 分开，既保留低摩擦工作台入口，又确保生成前已有最小可追溯事实基础。适中的演示限制提高本地可复现性而不建设泛化安全工程；分级冲突处理只阻断真正影响身份或关键事实的差异，符合适度校验原则。

## Impact

- PRD、MVP Scope、User Flows、Frontend Architecture、RFC-003 / 004 / 005、Testing Strategy 与 Goal 必须采用本输入契约。
- API 与前端必须能够区分 Task 创建成功、Fact Stage 可运行、单文件拒绝、Needs Input、阻断性冲突与非阻断性限制；具体公共枚举由 RFC-003 / RFC-004 冻结。
- 测试至少覆盖三字段任务创建、Fact Stage 最低门禁、无文件但结构化来源可运行、价格 / 卖点缺失不机械阻断、四项默认文件上限、同批文件部分接受、两类冲突行为和模型不得静默裁决阻断性冲突。
- 本决定不授权业务实现、Technical Spike 执行或实际 Goal 激活。
