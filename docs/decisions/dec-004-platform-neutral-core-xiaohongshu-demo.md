# DEC-004：产品核心保持平台中立，小红书种草作为首个 MVP 演示场景

## Type

Product

## Status

Accepted

## Decision

AI Ecommerce Agent 的核心商品定位分析与营销 Brief 能力保持平台中立，不将产品的底层业务流程、数据模型和 Agent 能力绑定到淘宝、小红书、抖音或其他单一平台。

MVP 在产品演示和作品集案例中，选择：**小红书商品种草** 作为首个具体展示场景。

系统应优先形成一份通用的商品定位与营销 Brief，并允许将通用分析结果映射为面向小红书种草场景的展示模板。

当前高层关系为：

```
商品资料与相关依据
        ↓
通用商品定位分析
        ↓
通用营销 Brief
        ↓
平台展示模板
        ↓
小红书种草 Brief
```

小红书模板是通用 Brief 的一种展示和适配方式，**不是**整个产品的唯一输出形态。

## Reason

完全平台中立虽然有利于控制产品边界，但容易使作品集案例过于抽象，难以向面试官展示具体的业务使用方式。

直接将产品绑定为小红书工具，又容易产生以下问题：

- 产品退化为小红书文案生成器；
- 业务能力过度依赖单个平台规则；
- 后续难以扩展到其他内容或电商平台；
- 通用商品分析能力与平台表达能力混在一起；
- 平台机制变化可能影响整个系统设计。

因此，采用「通用核心能力 + 小红书首个演示模板」的方式，可以同时获得：

- 清晰具体的演示场景；
- 平台中立的产品架构；
- 后续增加其他平台模板的扩展空间；
- 更清楚的通用分析层与平台适配层边界。

## Impact

该决定将影响：

- 产品定位描述；
- PRD 和 MVP Scope；
- User Flow；
- 营销 Brief 的数据结构；
- 平台适配层设计；
- Prompt、Skill 和模板设计；
- RAG 知识范围；
- 小红书案例数据准备；
- 前端结果展示；
- 项目 Demo；
- README 和简历项目描述；
- 后续开源项目筛选。

后续设计需要区分：

**通用层**，负责：

- 商品事实整理；
- 卖点提取；
- 目标用户分析；
- 用户需求与购买阻碍分析；
- 商品定位；
- 差异化表达；
- 通用营销策略；
- 通用营销 Brief。

**平台适配层**，负责将通用 Brief 转换为某个平台所需的表达结构。

MVP 的第一个平台适配层为：**小红书商品种草 Brief 模板。**

## Decision Boundary

**本决定已经确认：**

- 产品核心能力不绑定单一平台；
- 通用商品定位和营销 Brief 是核心；
- 小红书商品种草是首个 MVP 演示场景；
- 小红书输出应建立在通用分析结果之上；
- 后续可以增加其他平台模板。

**本决定尚未确认：**

- 小红书模板的具体字段；
- 是否生成完整小红书笔记；
- 是否生成标题、正文、话题标签或配图建议；
- 是否使用小红书官方创作指引；
- 是否抓取小红书公开内容；
- 是否分析小红书爆款笔记；
- 是否接入小红书 API；
- 是否自动发布内容；
- 是否支持淘宝、抖音或其他平台；
- 平台适配层的技术实现形式；
- 是否使用独立的平台 Agent 或 Skill。
