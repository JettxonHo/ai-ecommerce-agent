# DEC-006：MVP 输出采用四层结构化营销 Brief

## Type

Product

## Status

Accepted

## Decision

AI Ecommerce Agent 的 MVP 核心输出采用以下四层结构：

1. 事实层；
2. 洞察层；
3. 策略层；
4. 执行层。

系统首先形成可检查、可追溯的商品分析和营销决策依据，再形成供商品运营与内容运营人员使用的执行 Brief。

MVP **不以直接生成一篇完整小红书笔记作为核心交付目标**。

## Output Structure

### 第一层：事实层

用于记录有明确资料依据的信息，例如：

- 商品基本信息；
- 商品功能与参数；
- 价格或价格区间；
- 用户明确提供的卖点；
- 已知限制；
- 信息来源；
- 资料缺失项。

事实层**不得混入未经标记的模型推断**。

### 第二层：洞察层

基于事实和增强资料进行分析，例如：

- 潜在目标用户；
- 核心需求；
- 使用场景；
- 购买动机；
- 购买阻碍；
- 高频问题；
- 用户关注点。

洞察层中的内容需要区分：

- 有直接证据支持的结论；
- 基于有限资料形成的推断；
- 资料不足、暂时无法判断的事项。

### 第三层：策略层

形成面向商品运营和营销工作的业务判断，例如：

- 商品定位；
- 核心价值主张；
- 差异化表达；
- 卖点优先级；
- 内容传播角度；
- 需要避免的表达；
- 建议验证的假设。

### 第四层：执行层

将前面的分析转化为可供内容运营使用的结构化 Brief，例如：

- 内容目标；
- 目标受众；
- 核心信息；
- 内容角度；
- 支撑证据；
- 行动引导；
- 平台模板映射；
- 小红书种草 Brief。

> 具体字段、必填规则和输出格式仍需后续讨论。

## Core Principle

输出遵循：

```
事实
  ↓
洞察
  ↓
策略
  ↓
执行 Brief
```

后层内容应能够追溯到前层依据。

**不得出现：**

```
直接输入少量商品信息
        ↓
无依据生成完整营销文案
```

这种缺乏分析过程和证据关系的核心产品路径。

## Reason

采用四层结构可以：

- 避免产品退化为普通文案生成器；
- 帮助用户区分事实和模型推断；
- 让商品定位和营销建议更容易检查；
- 为后续引用、置信度和人工审核提供基础；
- 体现 Agent 在多步骤分析和业务决策支持上的价值；
- 让通用 Brief 与小红书平台模板保持清晰边界。

完整的小红书标题和正文虽然适合 Demo 展示，但如果被设为核心交付物，会削弱项目对商品分析、运营决策和结果可靠性的展示。

## Impact

该决定将影响：

- PRD；
- MVP Scope；
- User Flow；
- 营销 Brief 数据结构；
- 输出页面设计；
- 事实与推断标记；
- 引用和可追溯机制；
- Agent 状态设计；
- Skill 职责；
- RAG 输出使用方式；
- 质量评估指标；
- 小红书演示模板；
- 项目 Demo、README 和简历描述。

## Decision Boundary

**本决定已经确认：**

- MVP 输出采用事实、洞察、策略、执行四层结构；
- 四层之间应存在依据关系；
- 结构化营销 Brief 是核心交付物；
- 小红书 Brief 是执行层的一种平台映射；
- 完整小红书标题和正文暂不属于核心交付物。

**本决定尚未确认：**

- 四层的最终字段；
- 哪些字段必填；
- 输出使用 Markdown、JSON、表格还是其他格式；
- 引用的具体显示形式；
- 置信度计算方式；
- 是否生成标题和正文作为附加能力；
- 用户能否单独编辑某一层；
- 人工审核节点；
- Agent、RAG 与 Skill 的技术实现；
- 数据库存储方式。
