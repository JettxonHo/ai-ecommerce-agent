# DEC-003：MVP 核心任务为商品上新定位分析与营销 Brief 生成

## Type

Product

## Status

Accepted

## Decision

AI Ecommerce Agent 的 MVP 核心任务确定为：帮助中小电商商家的商品运营与内容运营人员，在商品上新或正式开展内容推广之前，完成商品定位分析，并生成可供后续内容策划和执行使用的结构化营销 Brief。

MVP 的基础任务闭环暂定为：

```
用户提交商品相关资料
        ↓
系统检查输入资料的完整性
        ↓
提取商品事实与核心卖点
        ↓
分析潜在目标用户
        ↓
分析用户需求、购买动机与购买阻碍
        ↓
形成商品定位与差异化表达
        ↓
形成内容方向和营销策略建议
        ↓
生成结构化营销 Brief
        ↓
执行质量检查并展示信息依据
```

该闭环描述的是当前确认的业务任务方向，**不代表**上述每一步的具体 Agent、技术实现和数据来源已经确定。

## Core Deliverable

MVP 的核心交付物为：**结构化商品上新营销 Brief。**

营销 Brief 后续至少可能包含：

- 商品基础事实；
- 商品核心卖点；
- 潜在目标用户；
- 用户需求；
- 购买动机；
- 购买阻碍；
- 商品定位；
- 差异化表达；
- 内容传播方向；
- 营销执行建议；
- 参考依据或引用。

> 注意：以上只是对交付物结构的初步边界描述。各字段是否全部进入 MVP、字段定义、输出格式和验收标准，仍需后续讨论，**不得在本次归档中擅自补全**。

## Reason

商品上新定位与营销 Brief 能够连接商品运营和内容运营两个角色：

- 商品运营负责整理商品、用户和竞争信息；
- 内容运营需要明确商品卖点、目标人群、内容角度和传播策略；
- 结构化 Brief 可以作为两个角色之间的协作交付物。

相较于其他候选方案：

1. 比单纯内容生成更能体现分析、判断和任务规划；
2. 比综合经营诊断更容易控制 MVP 范围；
3. 比消费者购物助手更符合商家运营场景；
4. 比单独评论分析更能形成从信息输入到业务交付物的完整闭环；
5. 可以自然承载后续 RAG、Skill、质量检查和人工确认设计。

## Impact

该决定将影响：

- PRD 中的核心产品目标；
- MVP Scope；
- User Flow；
- 输入资料范围；
- 输出数据结构；
- Agent 和 Skill 的职责设计；
- RAG 知识来源；
- 开源项目筛选标准；
- 前端交互设计；
- 验收与评估指标；
- 项目演示方式；
- README 和简历项目描述。

后续技术和功能设计必须围绕以下问题展开：这项能力是否有助于用户更准确、更高效地完成商品上新定位和营销 Brief？与该核心任务没有直接关系的能力，默认不进入 MVP。

## Decision Boundary

**本决定已经确认：**

- MVP 聚焦商品上新前的工作；
- 主要任务是商品定位分析；
- 最终形成结构化营销 Brief；
- 该 Brief 服务商品运营与内容运营协作。

**本决定尚未确认：**

- 具体适配哪个电商或内容平台；
- 用户必须提供哪些输入资料；
- 是否抓取公开网页；
- 是否必须使用用户评论；
- 是否必须进行竞品分析；
- Brief 的最终字段；
- 是否直接生成完整营销文案；
- 是否自动发布内容；
- 是否采用 LangGraph；
- 是否采用 RAG；
- Skill 的实现形式；
- 单 Agent 或 Multi-Agent；
- 具体模型、数据库与技术栈。
